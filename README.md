# Вариант 1 — ВКонтакте-бот с каталогом услуг

Домашнее задание к уроку VPi04 «Какой инструмент выбрать: сравнительный анализ».
Базовый вариант: разобрать кейсы урока и собрать бота с каталогом услуг через OpenCode.

---

## 1. Разбор трёх кейсов из урока

### Кейс 1. Исправление существующего проекта

**Задача:** исправить ошибки, улучшить архитектуру, провести рефакторинг и разобраться
в нескольких тысячах строк кода существующего интернет-магазина на Python.

**Выбор эксперта: Claude Code.**

**Почему.** Ключевой критерий здесь — объём проекта. Задача требует дословно изучить
большую кодовую базу, понять её структуру и предложить архитектурные изменения, не
сломав внешнее поведение. Это единственный критерий, по которому Claude Code выигрывает
с большим отрывом: модели Anthropic настроены на работу с большим объёмом кода.
Остальные инструменты тоже справятся, и эксперт это признаёт, но по первому критерию
выигрыш Claude Code перевешивает их преимущества.

**Что я вынес.** Объём кодовой базы — самый «весомый» критерий. Когда кода много и его
нужно понять целиком, остальные критерии уже не разворачивают решение.

---

### Кейс 2. Написание бота с нуля за один вечер

**Задача:** за вечер создать структуру проекта, написать код и быстро протестировать,
чтобы к утру всё работало.

**Выбор эксперта: Codex CLI.**

**Почему.** Здесь объём проекта работает наоборот: кода нет, глубокий анализ не требуется,
и преимущество Claude Code просто не востребовано. Остаётся инструмент, который сильнее
всех именно в генерации нового кода. Codex CLI быстро генерирует код, удобен при
последовательной разработке через терминал и умеет искать документацию в интернете —
за один проход находит нужное и делает. Главное — чтобы прототип к утру работал.

**Что я вынес.** Отсутствие большой кодовой базы — не нейтральная ситуация. Это
преимущество инструмента, который быстро пишет. Отсутствие кода — такой же сильный
сигнал, как его наличие.

---

### Кейс 3. Ежедневная работа с разными моделями

**Задача:** разработчик ежедневно пишет небольшие проекты, и ему в разные дни нужны то
GPT, то Claude, то Gemini, то DeepSeek, то локальная модель.

**Выбор эксперта: OpenCode.**

**Почему.** Здесь решает критерий доступности и гибкости. Claude Code работает только
с моделями Anthropic, Codex CLI — только с моделями OpenAI. Чтобы переключиться, нужно
закрыть одну среду и открыть другую, продолжив работу в ней. Каждый переход тратит токены
и время, а контекст теряется. OpenCode меняет модель одной командой — в том же чате,
с тем же контекстным окном. Плюс доступны бесплатные модели и нет проблем с региональными
ограничениями.

**Что я вынес.** Главная выгода OpenCode — не столько число моделей, сколько отсутствие
потери контекста при переключении. Именно это превращает набор инструментов в рабочую среду.

---

## 2. Почему для этого бота выбран OpenCode

Это ровно тот вопрос, который задаёт урок про кейс с ВКонтакте-ботом. Причины из урока
и мои проверки:

1. **Можно подобрать модель под язык и задачу.** Проект на Python, и при желании модель
   можно сменить, не начиная проект заново.
2. **Легко переключаться между моделями, не меняя среду.** Весь код писался через
   OpenCode: модель менялась прямо по ходу работы, когда выяснялось, что задача
   структурная, а не творческая.
3. **Можно использовать бесплатные модели.** Для учебного проекта это обязательное
   условие, а не приятный бонус. Все промпты и весь код сделаны на бесплатных моделях.
4. **Проект небольшой и делается с нуля.** Глубокий анализ большой кодовой базы здесь
   не нужен — значит, главное преимущество Claude Code не работает.

Что было бы при других инструментах, если бы задача изменилась:

| Если задача изменится на… | Тогда выбираем |
|---------------------------|---------------|
| Бот станет частью большого проекта с десятками модулей, услуги подтягиваются из 1С | **Claude Code** |
| Нужно максимально быстро написать новый проект | **Codex CLI** |
| Нужно проверять работу бота в проде и в тестовой среде одновременно, разные модели | **OpenCode** |
